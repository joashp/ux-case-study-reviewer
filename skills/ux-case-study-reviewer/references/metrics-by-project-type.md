# Metrics by project type

Use with `/proof`. Suggest what to find or estimate. Never invent numbers for the user. If a figure is unknown, use a placeholder and say how to get it.

## Quick menu

| Project type | Strong metrics | Where to find them |
|---|---|---|
| Onboarding / signup | Activation rate, time to first value, step drop-off | Product analytics, funnel reports |
| Checkout / conversion | Conversion rate, cart abandonment, payment errors | Analytics, e-commerce platform |
| Dashboard / data tool | Task completion time, support questions, feature adoption | Usability tests, usage logs |
| Mobile app feature | Feature adoption, retention (D7/D30), crash or error rate | Analytics, store reviews |
| Design system | Component reuse, design-to-dev handoff time, UI inconsistencies fixed | Audits, repo usage, team survey |
| Redesign / usability fix | Task success rate, time on task, SUS or satisfaction score | Usability test before and after |
| Research-only project | Insights adopted, decisions changed, stakeholders aligned | Roadmap changes, meeting notes |
| Internal tool | Hours saved, error reduction, training time | Team interviews, time logs |
| Accessibility work | WCAG issues resolved, audit score, assistive-tech task success | Audit tools, screen-reader tests |

## When there are no numbers
Characterize impact honestly and say how you know:
- "Support tickets about this flow dropped noticeably after launch (per the support lead)."
- "Five of six usability participants completed the task unaided, up from two of six."
- "The team adopted the new pattern in the next three features."

Small samples are fine. State the sample size so they read as honest, not inflated.

## Student, bootcamp and concept projects
No live analytics is normal. Strong substitutes:
- Usability test results (even 5 participants), with task success and quotes
- Before and after comparison against the original design
- Stakeholder or mentor feedback, attributed
- Clear success criteria set at the start, and how the design meets them

## Quality checks before suggesting a metric
- Is it tied to the problem stated at the start? If the problem was drop-off, report drop-off.
- Does it have a baseline? "44% activation" means nothing without the before figure.
- Did the design plausibly cause it? Flag anything else that changed (a marketing push, seasonality).
- Is it a vanity number (page views, likes)? Replace it with a behaviour or outcome metric.
